# Product Spec

## 1. 문서 목적

이 문서는 `personal-resume-management`가 **무엇을 해결하려는 도구인지**를 먼저 고정하기 위한 제품 초안입니다.

기능을 상상해서 채우기보다, 이미 확인된 목적과 현재 작업 흐름에서 필요한 관리 단위를 기준으로 작성합니다.

---

## 2. 제품 목적

### 확정

개인 이력서 관리 과정을 더 편하게 만드는 개인용 프로그램을 만든다.

### 가설

현재 취업 준비 과정에서는 하나의 이력서를 계속 덮어쓰기보다 다음과 같은 정보가 반복해서 수정·재사용됩니다.

- 마스터 이력서의 기본 정보
- 프로젝트·경험별 서술
- 지원 직무나 공고에 따라 달라지는 강조점
- 자기소개 문단 또는 모듈
- 회사별 제출본과 수정 이력

따라서 이 프로그램은 **원본 정보를 한곳에서 관리하고, 지원 목적에 따라 필요한 조합을 만들기 쉽게 하는 것**을 우선 목표로 둡니다.

이 항목은 실제 화면과 데이터 구조를 설계하면서 다시 검증합니다.

---

## 3. 제품 원칙

### 확정

1. **원본과 지원용 변형본을 구분한다.**
   - 기준이 되는 정보와 특정 지원처에 맞춘 수정본이 섞이지 않도록 한다.

2. **사용자가 하지 않은 경험이나 수치를 만들어내지 않는다.**
   - 저장된 사실을 기준으로 문서를 구성한다.

3. **민감정보를 공개 저장소에 넣지 않는다.**
   - 전화번호, 이메일 등 실제 이력서의 개인정보는 코드 저장소와 분리한다.

4. **확정된 사실과 임시 판단을 구분한다.**
   - 기능·정책 문서에서도 `확정 / 가설 / TBD` 상태를 유지한다.

---

## 4. 관리 단위 초안

아래는 현재 이력서 작업 방식을 기준으로 잡은 **가설 단계의 관리 단위**입니다.

| 관리 단위 | 목적 | 상태 |
| --- | --- | --- |
| Master Resume | 기준이 되는 이력서 정보 관리 | 가설 |
| Experience / Project | 프로젝트·경력·활동별 사실과 서술 관리 | 가설 |
| Intro Module | 자기소개 문단을 목적별로 재사용 | 가설 |
| Application Variant | 특정 회사·공고에 맞춘 제출본 관리 | 가설 |
| Revision History | 수정 전후와 변경 이유 확인 | 가설 |

현재 자기소개는 P1~P4처럼 목적에 따라 조합해 사용하는 흐름이 이미 있으므로, 향후 데이터 구조를 설계할 때 모듈화 가능성을 우선 검토합니다.

- 변형본이 어떤 원본 항목을 사용했는지 확인

## 6. 다음 설계 단계

다음 구현 단계에서는 기능을 바로 늘리지 않고 아래 순서로 정리합니다.

1. 실제로 가장 자주 수정하는 데이터 단위 확인
2. Master와 Variant의 관계 정의
3. 개인정보 저장 위치 결정
4. 최소 화면 흐름 정의
5. 데이터 모델 확정
6. 구현 시작

기능을 추가할 때는 이 문서의 목적에 직접 필요한지 먼저 확인합니다.
