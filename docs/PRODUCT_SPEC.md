# Product Spec

## 1. 제품 목적

### 확정

`personal-resume-management`의 1차 목적은 **채용 지원용 PDF 이력서를 쉽게 작성·편집·관리하는 개인용 Resume Builder**를 만드는 것입니다.

단순한 HTML 이력서 파일이 아니라 다음을 지원합니다.

- 이력서 각 섹션 직접 편집
- 항목 추가·삭제
- 항목 순서 변경
- 항목 표시·숨김
- 직무/용도와 지원처에 따라 구성과 강조점 변경
- A4 PDF 출력
- 집 PC와 노트북 등 여러 기기에서 같은 이력서 데이터 사용
- 웹에서는 누구나 이력서를 볼 수 있지만 편집은 본인만 가능

### 결정 이유

- 최근 지원처는 대부분 PDF 이력서를 요구함
- 기존 Resume Builder의 편집 UX는 편했지만 기본 템플릿과 정보 구조에는 한계가 있었음
- 쉽게 수정하는 사용성은 유지하면서 이력서 구조와 디자인을 직접 설계하기로 함

---

## 2. 장기 방향

### 확정 방향

현재는 PDF 이력서 제작을 우선합니다.

첫 직장 이후에는 개인 커리어 관리, 경력 소개, 헤드헌팅 등에 활용할 수 있는 **개인 커리어 웹사이트**로 확장할 가능성을 열어둡니다.

다만 현재 단계에서 장기 기능을 미리 과도하게 구현하지 않습니다.

---

## 3. MVP 기능 범위

### 확정

#### 이력서 편집

- 섹션별 내용 직접 편집
- 항목 추가
- 항목 삭제
- 항목 순서 변경
- 항목 표시/숨김
- 직무/용도와 지원처에 맞게 일부 구성과 강조 순서를 변경할 수 있는 구조

기존 Resume Builder처럼 **완성된 이력서 화면 자체에서 섹션을 클릭해 편집하고, 바깥 영역을 클릭하면 편집을 종료하면서 자동 저장되는 사용성**을 지향합니다.

자동 저장은 현재 버전의 최신 상태를 갱신하는 동작이며, 자동 저장마다 새 버전을 만들지는 않습니다.

#### 여러 기기에서 사용

- 집 PC와 노트북 등 다른 단말에서도 동일한 데이터를 사용
- `localStorage`만으로 끝내지 않고 클라우드 저장 사용

#### PDF 출력

- 채용 제출용 최우선 결과물은 PDF
- A4 기준 출력
- 페이지 수를 1p/2p/3p로 미리 고정하지 않음

세부 출력 규칙은 [DESIGN_PRINT_SPEC.md](DESIGN_PRINT_SPEC.md)에서 관리합니다.

## 4. 직무/용도, 지원처, 이력서 버전 관리

### 확정

이력서 관리 계층은 아래처럼 구성합니다.

```text
직무/용도
└─ 지원처 또는 공통본
   └─ 이력서 버전
```

예:

```text
웹툰·콘텐츠 PM
├─ 공통본
│  ├─ v1.0
│  └─ v1.1
├─ 네이버웹툰 · 서비스기획
│  ├─ v1.0
│  └─ v1.1
└─ 카카오엔터 · 플랫폼기획
   └─ v1.0

게임 PM
├─ 공통본
└─ 시프트업 · 서비스기획
   └─ v1.0
```

### 직무/용도

- 최상위 그룹
- 이름은 자유 입력
- 예: `웹툰·콘텐츠 PM`, `게임 PM`, `인터넷방송 플랫폼`, `범용 서비스기획`
- `마스터`가 필요하면 특별한 시스템 개체를 두지 않고 일반 직무/용도 또는 지원처 이름으로 자유롭게 사용 가능

### 지원처 / 공통본

- 실제 지원 단계까지 간 경우에만 회사명을 선택적으로 붙일 수 있음
- 회사명이 없는 직무별 공통본도 허용
- 특정 회사에 묶이지 않은 베이스 이력서를 계속 관리할 수 있음

### 새 이력서 / 버전 생성

사용자는 자유롭게 다음 방식 중 하나를 선택할 수 있습니다.

- 빈 이력서로 시작
- 같은 지원처의 기존 버전을 복제
- 다른 지원처 또는 다른 직무/용도의 원하는 버전을 복제

어느 버전도 특별한 원본으로 강제하지 않습니다. 그때그때 가장 적합한 기존 버전을 출발점으로 선택할 수 있게 합니다.

### 버전 번호

버전은 `v{major}.{minor}` 형식을 기본으로 사용합니다.

- **Major**: 방향이나 구성이 크게 달라지는 수정
  - 예: 자기소개 방향 변경, 프로젝트 구성 대폭 변경, 섹션 구조 재설계
- **Minor**: 기존 방향 안에서의 비교적 작은 수정
  - 예: 일부 문구 수정, 프로젝트 일부 교체, 순서 조정, 표현 보완

예:

```text
v1.0 → v1.1 → v1.2 → v2.0
```

새 버전은 사용자가 명시적으로 `새 버전 만들기`를 선택했을 때 생성합니다. 생성 시 Major / Minor 중 하나를 선택하면 번호를 자동 증가시키는 방향으로 설계합니다.

### 버전 메타정보

각 버전은 최소한 다음 메타정보를 가집니다.

- 버전 번호
- 선택적 라벨 / 설명
- 생성 일시
- 최종 수정 일시
- 복제해 만든 경우 원본 직무/용도 · 지원처 · 버전 정보

예:

```text
v1.2 · 자기소개 수정
2026.09.15 생성 · 2026.09.15 수정
```

버전 라벨은 사용자가 직접 수정할 수 있게 합니다. 예: `v2.0 · 최종 제출본`.

### 자동 저장과 히스토리

자동 저장과 버전 생성은 분리합니다.

- 섹션 편집 후 바깥을 클릭하면 현재 버전에 자동 저장
- 자동 저장만으로 버전 번호는 증가하지 않음
- 현재 버전 안에서는 가벼운 변경 히스토리를 남길 수 있게 함
- 중요한 시점은 사용자가 새 Major / Minor 버전으로 직접 저장

## 5. 홈과 편집 진입 방식

### 확정

홈은 전체 이력서 관리 화면입니다.

- 상단에 **최근 작업 이어하기 1개** 노출
- 아래에 **직무/용도 탭** 배치
- 기본 선택 탭은 가장 최근 작업한 이력서가 속한 직무/용도
- 선택한 탭 아래에 지원처/공통본을 카드형으로 표시
- 지원처 카드를 클릭하면 과거 버전 목록이 아니라 **최신 버전을 바로 열기**
- 과거 버전은 필요할 때 별도 버전 관리 UI에서 확인

세부 UX는 [EDITOR_UX_SPEC.md](EDITOR_UX_SPEC.md)에서 관리합니다.

## 6. 삭제 정책

### 확정

데이터 관리를 위해 삭제 기능을 반드시 지원합니다.

삭제 범위는 최소한 다음을 포함합니다.

- 개별 이력서 버전 삭제
- 특정 지원처/공통본과 그 아래 모든 버전 삭제
- 특정 직무/용도와 그 아래 모든 지원처·버전 삭제

특정 지원처 전체 또는 직무/용도 전체처럼 **하위 데이터를 함께 제거하는 대량 삭제**는 실수 방지를 위해 별도 확인 절차를 둡니다.

사용자가 확인창에서 정확히 `삭제`를 입력해야 최종 삭제 버튼이 활성화되도록 합니다.

확인창에는 무엇이 삭제되는지 범위를 명확히 표시합니다.

전역 전체 데이터 삭제는 현재 MVP 요구사항으로 별도 확정하지 않습니다.

## 7. 데이터 구조 요구사항

### 확정된 요구사항

데이터 구조는 최소한 다음 동작을 지원해야 합니다.

- 직무/용도 자유 생성 및 관리
- 직무/용도 하위의 지원처/공통본 관리
- 지원처 내부의 여러 이력서 버전 관리
- 빈 이력서에서 시작
- 같은 지원처 또는 다른 지원처/직무의 특정 버전 복제
- Major / Minor 버전 번호 관리
- 버전 라벨, 생성 일시, 수정 일시 관리
- 현재 버전의 자동 저장
- 버전별 가벼운 변경 히스토리 관리
- 최근 작업 이력서 식별
- 섹션별 데이터 관리
- 항목 추가/삭제
- 항목 순서 변경
- 표시/숨김
- 여러 기기에서 같은 데이터 사용
- 계층별 범위 삭제

### 프로젝트 데이터에서 합의된 개념 필드

- 프로젝트명
- 설명 / 한 줄 정의
- 기간
- 팀 규모
- 역할
- Abstract 1
- Abstract 2
- Abstract 3
- 링크
- 표시 여부

위 항목은 **개념적 편집 필드**이며 실제 DB/API 스키마는 아직 확정하지 않았습니다.

## 8. 사용자 흐름

### 공개 사용자

1. 웹사이트 접속
2. 이력서 열람
3. 웹 형태 또는 PDF 결과 확인

### 편집 사용자

1. 웹사이트 접속
2. 편집 요청
3. 로컬 Authenticator로 Challenge-Response 인증
4. 인증 성공
5. 홈에서 최근 작업을 이어가거나 직무/용도 탭 선택
6. 지원처/공통본 카드 선택
7. 해당 카드의 최신 버전 편집 화면 진입
8. 섹션 클릭 후 내용 수정
9. 바깥 영역 클릭 시 현재 버전에 자동 저장
10. 필요하면 Major / Minor 새 버전 생성
11. 필요하면 다른 버전을 복제해 새 지원처 또는 버전 생성
12. PDF 출력
13. 마지막 활동을 기준으로 1시간 동안 편집 세션 유지

인증 세부사항은 [AUTH_SECURITY_SPEC.md](AUTH_SECURITY_SPEC.md)에서 관리합니다.

## 9. 이력서 콘텐츠 원칙

### 확정

- 이력서는 프로젝트·경력의 요약과 면접 질문의 출발점으로 사용
- 상세 문제 해결 과정은 포트폴리오에서 설명
- 프로젝트별 Tools 반복 나열 대신 별도 Skills 섹션 사용
- 직무/용도와 지원처별로 프로젝트 순서와 표시 여부를 조정할 수 있게 함

세부 섹션 구조는 [RESUME_STRUCTURE.md](RESUME_STRUCTURE.md)에서 관리합니다.

## 10. 아직 미확정

### 기술

- 프론트엔드 프레임워크
- 백엔드 구현 방식
- 데이터베이스 / 클라우드 저장소 제공자
- 실제 DB 테이블 구조
- 변경 히스토리의 보존 개수 / 기간
- 히스토리에서 실제 이전 상태로 복원할 수 있게 할지 여부
- 이미지 / 사진 저장 방식

### UX

- 과거 버전 관리 화면의 구체 레이아웃
- 개별 버전 삭제 시 확인 UX 강도
- 삭제 후 복구 가능한 휴지통을 둘지 여부
- 직무/용도 탭 직접 정렬 지원 여부
- 직무/용도 수가 많아졌을 때 검색/필터 필요 여부

### 콘텐츠

- 자기소개 최종 문구
- 프로젝트 Abstract 최종 문구
- Skills 최종 분류와 목록
- 직무 교육 최종 노출 목록
- 전공/교양 선택 이유 최종 문구
- Awards/Activities 최종 목록
- 지원처별 버전별 콘텐츠
