# Product Spec

## 1. 제품 목적

### 확정

`personal-resume-management`의 1차 목적은 **채용 지원용 PDF 이력서를 쉽게 작성·편집·관리하는 개인용 Resume Builder**를 만드는 것입니다.

단순한 HTML 이력서 파일이 아니라 다음을 지원합니다.

- 이력서 각 섹션 직접 편집
- 항목 추가·삭제
- 항목 순서 변경
- 항목 표시·숨김
- 지원처에 따라 구성과 강조점 변경
- A4 PDF 출력
- 집 PC와 노트북 등 여러 기기에서 같은 이력서 데이터 사용
- 웹에서는 누구나 이력서를 볼 수 있지만 편집은 본인만 가능

### 결정 이유

- 최근 지원처는 대부분 PDF 이력서를 요구함
- 기존 Resume Builder의 편집 UX는 편했지만 기본 템플릿과 정보 구조에는 한계가 있었음
- 쉽게 수정하는 사용성은 유지하면서 이력서 구조와 디자인을 직접 설계하기로 함

---

## 2. 장기 방향

### 확정 방향

현재는 PDF 이력서 제작을 우선합니다.

첫 직장 이후에는 개인 커리어 관리, 경력 소개, 헤드헌팅 등에 활용할 수 있는 **개인 커리어 웹사이트**로 확장할 가능성을 열어둡니다.

다만 현재 단계에서 장기 기능을 미리 과도하게 구현하지 않습니다.

---

## 3. MVP 기능 범위

### 확정

#### 이력서 편집

- 섹션별 내용 직접 편집
- 항목 추가
- 항목 삭제
- 항목 순서 변경
- 항목 표시/숨김
- 지원처에 맞게 일부 구성과 강조 순서를 변경할 수 있는 구조

기존 Resume Builder처럼 **화면에서 내용을 누르면 바로 편집할 수 있는 사용성**을 지향합니다.

#### 여러 기기에서 사용

- 집 PC와 노트북 등 다른 단말에서도 동일한 데이터를 사용
- `localStorage`만으로 끝내지 않고 클라우드 저장 사용

#### PDF 출력

- 채용 제출용 최우선 결과물은 PDF
- A4 기준 출력
- 페이지 수를 1p/2p/3p로 미리 고정하지 않음

세부 출력 규칙은 [DESIGN_PRINT_SPEC.md](DESIGN_PRINT_SPEC.md)에서 관리합니다.

---

## 4. 마스터 데이터와 지원처별 버전

### 확정

하나의 마스터 데이터를 기반으로 지원처별 이력서 버전을 만들 수 있는 구조를 지향합니다.

지원처별로 변경할 수 있는 요소 예시:

- 지원 직무명
- 자기소개
- 프로젝트 순서
- 프로젝트 표시/숨김
- 강조 항목

웹툰·인터넷방송·콘텐츠·서브컬처·게임 등 여러 분야를 지원할 수 있으므로 이력서 기본 구조를 하나의 도메인 키워드에 고정하지 않습니다.

---

## 5. 데이터 구조 요구사항

### 확정된 요구사항

데이터 구조는 최소한 다음 동작을 지원해야 합니다.

- 섹션별 데이터 관리
- 항목 추가/삭제
- 항목 순서 변경
- 표시/숨김
- 지원처별 구성 변경
- 여러 기기에서 같은 데이터 사용

### 프로젝트 데이터에서 합의된 개념 필드

- 프로젝트명
- 설명 / 한 줄 정의
- 기간
- 팀 규모
- 역할
- Abstract 1
- Abstract 2
- Abstract 3
- 링크
- 표시 여부

위 항목은 **개념적 편집 필드**이며 실제 DB/API 스키마는 아직 확정하지 않았습니다.

---

## 6. 사용자 흐름

### 공개 사용자

1. 웹사이트 접속
2. 이력서 열람
3. 웹 형태 또는 PDF 결과 확인

### 편집 사용자

1. 웹사이트 접속
2. 편집 요청
3. 로컬 Authenticator로 Challenge-Response 인증
4. 인증 성공
5. 편집 모드 진입
6. 섹션 및 항목 수정
7. 클라우드에 저장
8. PDF 출력
9. 마지막 활동을 기준으로 1시간 동안 편집 세션 유지

인증 세부사항은 [AUTH_SECURITY_SPEC.md](AUTH_SECURITY_SPEC.md)에서 관리합니다.

---

## 7. 이력서 콘텐츠 원칙

### 확정

- 이력서는 프로젝트·경력의 요약과 면접 질문의 출발점으로 사용
- 상세 문제 해결 과정은 포트폴리오에서 설명
- 프로젝트별 Tools 반복 나열 대신 별도 Skills 섹션 사용
- 지원처별로 프로젝트 순서와 표시 여부를 조정할 수 있게 함

세부 섹션 구조는 [RESUME_STRUCTURE.md](RESUME_STRUCTURE.md)에서 관리합니다.

---

## 8. 아직 미확정

### 기술

- 프론트엔드 프레임워크
- 백엔드 구현 방식
- 데이터베이스 / 클라우드 저장소 제공자
- 실제 DB 테이블 구조
- 지원처별 버전 저장 방식
- 버전 히스토리 / 스냅샷 저장 여부
- 이미지 / 사진 저장 방식

### 콘텐츠

- 자기소개 최종 문구
- 프로젝트 Abstract 최종 문구
- Skills 최종 분류와 목록
- 직무 교육 최종 노출 목록
- 전공/교양 선택 이유 최종 문구
- Awards/Activities 최종 목록
- 지원처별 버전별 콘텐츠
