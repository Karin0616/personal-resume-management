# GPT Integration Spec

## 1. 목적

Resume Builder의 데이터를 ChatGPT에서 읽어와 함께 검토하고, 수정 결과를 앱에 다시 넣기 쉬운 고정 형식으로 출력할 수 있게 합니다.

현재 MVP에서는 ChatGPT가 Resume Builder의 데이터를 직접 수정하는 write 연동을 필수로 하지 않습니다.

핵심 흐름은 다음과 같습니다.

```text
Resume Builder
  ↓ 읽기
ChatGPT / MCP
  ↓
이력서 내용 확인·상담·수정안 작성
  ↓
앱이 이해할 수 있는 고정 형식으로 출력
  ↓
사용자가 복사
  ↓
Resume Builder의 GPT 결과 가져오기에 붙여넣기
  ↓
변경 내용 미리보기
  ↓
사용자가 적용
```

---

## 2. 확정 원칙

### MCP는 우선 읽기 중심으로 사용

ChatGPT가 다음 정보를 읽어올 수 있도록 API 구조를 설계합니다.

- 직무/용도 목록
- 지원처/공통본 목록
- 버전 목록
- 특정 버전의 이력서 데이터
- 필요한 경우 버전 메타정보와 변경 히스토리

MVP에서 ChatGPT가 DB에 직접 create/update/delete를 수행하는 기능은 필수가 아닙니다.

### 최종 반영은 사용자가 수행

ChatGPT와 수정안을 상의한 뒤, 최종 결과는 Resume Builder가 받아들일 수 있는 고정 포맷으로 출력합니다.

사용자는 이를 앱에 붙여넣고 변경 내용을 확인한 뒤 직접 적용합니다.

이 구조는 다음 장점이 있습니다.

- ChatGPT의 직접 쓰기 권한 없이도 사용 가능
- 적용 전 사용자가 변경 내용을 확인 가능
- 잘못된 수정이나 범위 초과 변경을 방지하기 쉬움
- 향후 write MCP를 지원하더라도 같은 Resume API를 재사용 가능

---

## 3. GPT 결과 가져오기

편집 화면 또는 관리 UI에서 `GPT 결과 가져오기` 기능을 제공합니다.

기본 흐름:

1. ChatGPT가 지정된 포맷으로 결과 출력
2. 사용자가 전체 결과를 복사
3. Resume Builder의 `GPT 결과 가져오기`에 붙여넣기
4. 앱이 포맷을 파싱하고 대상 섹션과 변경 내용을 확인
5. 변경 전 / 변경 후 미리보기 제공
6. 사용자가 `적용`을 눌러 현재 버전에 반영
7. 반영 결과는 일반 편집과 동일하게 현재 버전에 저장

붙여넣은 결과가 잘못된 형식이거나 존재하지 않는 필드를 가리키면 즉시 적용하지 않고 오류를 안내합니다.

---

## 4. 출력 포맷

사람이 읽고 복사하기 쉬우면서 앱이 안정적으로 파싱할 수 있도록 **JSON 기반 포맷**을 기본으로 합니다.

예시:

```json
{
  "schema_version": "1.0",
  "target": {
    "section": "projects",
    "item_id": "allblu"
  },
  "changes": {
    "summary": "웹툰·애니메이션 감상 기록과 사용자 추천을 연결한 소셜 아카이빙 서비스",
    "abstracts": [
      "사용자 조사와 행동 데이터를 바탕으로 핵심 탐색 경험의 문제를 정의했습니다.",
      "PRD·정책·GA4 트래킹을 설계하고 개발자와 MVP 개선을 진행했습니다.",
      "콘텐츠 운영 자동화를 설계해 처리 시간을 87.5% 단축했습니다."
    ]
  }
}
```

### 포맷 원칙

- `schema_version`으로 향후 포맷 변경에 대응
- 대상 섹션과 항목을 명시
- 변경할 필드만 `changes`에 포함
- 없는 경험·수치·필드는 임의 생성하지 않음
- 앱이 알 수 없는 필드는 적용하지 않음
- 한 번의 출력에서 여러 섹션 변경도 지원할 수 있도록 확장 가능하게 설계

실제 ID와 DB 필드명은 데이터 모델을 확정할 때 최종 결정합니다.

## 5. Resume API 설계 원칙

웹 UI가 DB를 직접 조작하는 구조에 강하게 결합하지 않고, Resume API 계층을 통해 데이터를 읽고 쓰도록 설계합니다.

```text
Web UI ───────┐
              ├─ Resume API ─ DB / Storage
MCP / GPT ────┘
```

이를 통해 웹앱과 MCP가 동일한 데이터 모델과 검증 규칙을 공유할 수 있게 합니다.

MVP에서는 MCP가 읽기 API만 사용하더라도, 향후 다음 기능을 추가할 수 있습니다.

- 새 버전 생성
- 특정 버전 복제
- 섹션 수정
- 히스토리 조회
- 지원처 생성

삭제 기능은 향후 write MCP를 지원하더라도 별도 사용자 확인 없이 자동 실행하지 않는 방향을 기본으로 합니다.

---

## 6. ChatGPT에서 기대하는 사용 예시

```text
"웹툰·콘텐츠 PM의 네이버웹툰 최신 버전 읽어와줘."

"ALLBLU 프로젝트 부분을 이 JD 기준으로 같이 수정해보자."

"방금 확정한 수정안을 Resume Builder 붙여넣기 형식으로 출력해줘."
```

ChatGPT는 현재 이력서 데이터를 읽은 뒤 사용자와 수정 방향을 상의하고, 최종 확정된 내용만 앱 입력 포맷으로 출력합니다.

---

## 7. MVP / 이후 구분

### MVP에 포함

- Resume API가 향후 MCP에서 읽을 수 있는 구조
- GPT 결과 가져오기 입력창
- JSON 포맷 검증
- 변경 내용 미리보기
- 사용자의 명시적 적용

### 이후 확장

- 실제 MCP 서버 연결
- ChatGPT에서 이력서 데이터 직접 조회
- 여러 섹션 일괄 변경 포맷
- write MCP를 통한 직접 수정
- ChatGPT에서 버전 생성·복제

직접 쓰기 기능이 추가되더라도 사용자의 데이터 삭제나 광범위한 변경은 별도 확인 절차를 유지합니다.
