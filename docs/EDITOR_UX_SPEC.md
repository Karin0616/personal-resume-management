# Editor UX Spec

## 1. 기본 원칙

### 확정

편집 UX는 **자유도와 편의성**을 우선합니다.

- 완성된 이력서 화면 자체가 편집 화면이 됩니다.
- 섹션을 클릭하면 해당 영역만 편집 상태로 전환합니다.
- 바깥 영역을 클릭하면 편집을 종료하고 현재 버전에 자동 저장합니다.
- 자동 저장은 현재 버전의 최신 상태만 갱신하며 새 버전을 만들지 않습니다.

---

## 2. 홈 화면 구조

### 확정

홈 화면은 이력서를 관리하는 시작점입니다.

상단에는 **최근 작업 이어하기 1개**를 크게 보여줍니다.

최근 작업 카드에는 최소한 다음 정보를 노출할 수 있습니다.

- 직무/용도
- 회사명 또는 지원처명(있는 경우)
- 현재 버전
- 최종 수정 시각

카드를 누르면 마지막으로 작업하던 이력서 버전의 편집 화면으로 바로 이동합니다.

그 아래에는 **직무/용도 탭**을 둡니다.

예:

```text
웹툰·콘텐츠 PM | 게임 PM | 범용 서비스기획 | 인터넷방송 플랫폼 | + 새 용도
```

직무/용도명은 자유 입력입니다.

홈에 처음 진입했을 때 기본 선택 탭은 **가장 최근에 작업한 이력서가 속한 직무/용도**로 합니다.

---

## 3. 직무/용도와 지원처 구조

### 확정

상위 단위는 **직무/용도**입니다.

실제 회사 지원까지 간 경우에만 회사명을 선택적으로 붙여 관리합니다.

예:

```text
웹툰·콘텐츠 PM
├─ 공통본
├─ 네이버웹툰 · 서비스기획
└─ 카카오엔터 · 플랫폼기획

게임 PM
├─ 공통본
└─ 시프트업 · 서비스기획
```

- 직무/용도는 자유롭게 생성 가능
- 회사명은 선택 사항
- 특정 회사에 묶이지 않은 공통본도 생성 가능
- `마스터`가 필요하면 일반 직무/용도 또는 일반 지원처 이름으로 자유롭게 사용 가능

---

## 4. 카드 목록

### 확정

선택한 직무/용도 탭 아래에는 기존 Resume Builder처럼 **카드형 목록**을 사용합니다.

각 카드는 해당 지원처/공통본을 나타냅니다.

카드에는 과도한 정보를 넣지 않고 다음 정도를 우선합니다.

- 지원처/공통본 이름
- 현재 최신 버전
- 마지막 수정 시각
- 버전 수
- 선택적 라벨(예: 제출본)

지원처 카드를 클릭하면 과거 버전 목록을 먼저 보여주지 않고 **최신 버전을 바로 엽니다.**

과거 버전은 별도의 버전 관리 UI에서 필요할 때 확인합니다.

---

## 5. 새 직무/용도, 지원처, 버전 생성

### 확정

새 이력서는 다음 방식으로 시작할 수 있습니다.

- 빈 이력서로 시작
- 같은 직무/용도의 기존 버전 복제
- 다른 직무/용도 또는 다른 지원처의 특정 버전 복제

어느 버전도 시스템적으로 특별한 원본으로 강제하지 않습니다.

사용자는 그때그때 가장 마음에 드는 기존 버전을 선택해 새 이력서의 출발점으로 사용할 수 있습니다.

---

## 6. 버전 관리

### 확정

버전은 `v{major}.{minor}` 형식을 기본으로 사용합니다.

```text
v1.0 → v1.1 → v1.2 → v2.0
```

- Major: 방향이나 구성이 크게 달라지는 변경
- Minor: 기존 방향 안에서의 비교적 작은 변경
- 새 버전은 사용자가 `새 버전 만들기`를 명시적으로 선택했을 때만 생성
- 생성 시 Major / Minor를 선택하면 번호를 자동 증가
- 자동 저장은 버전 번호를 증가시키지 않음

버전 번호와 별도로 다음 정보를 관리합니다.

- 선택적 라벨
- 생성 일시
- 최종 수정 일시
- 복제 원본 정보

예:

```text
v1.2 · 자기소개 수정
2026.09.15 생성 · 2026.09.15 수정
```

## 7. 삭제 정책

### 확정

데이터 관리를 위해 삭제 기능을 반드시 지원합니다.

삭제 범위는 계층에 따라 구분합니다.

- 개별 버전 삭제
- 특정 지원처의 전체 버전 삭제
- 특정 직무/용도 아래의 전체 데이터 삭제

대량 삭제는 실수 방지를 위해 일반 확인 버튼만으로 실행하지 않습니다.

**특정 지원처 전체 또는 특정 직무/용도 전체처럼 하위 데이터를 함께 지우는 삭제는 확인창에서 `삭제`라는 키워드를 직접 입력해야 최종 실행할 수 있게 합니다.**

확인창에는 삭제 범위를 명확하게 표시합니다.

예:

```text
'웹툰·콘텐츠 PM' 아래의 지원처와 모든 이력서 버전을 삭제합니다.
이 작업을 계속하려면 아래에 '삭제'를 입력하세요.
```

전역 전체 데이터 삭제와 같은 더 큰 범위는 현재 MVP 요구사항으로 별도 확정하지 않습니다.

---

## 8. 아직 미확정

- 탭의 직접 드래그 정렬 지원 여부
- 탭이 많아졌을 때 좌우 스크롤 외 추가 검색/필터 필요 여부
- 과거 버전 관리 화면의 구체 레이아웃
- 개별 버전 삭제 시 확인 UX 강도
- 삭제 후 복구 가능한 휴지통을 둘지 여부
- 히스토리에서 이전 상태를 복원할 수 있게 할지 여부
